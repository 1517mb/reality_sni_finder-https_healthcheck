# REALITY SNI Finder & HTTPS Healthcheck

[English](README.md) | **Русский**

Два самостоятельных консольных скрипта для поиска SNI-кандидатов для Xray REALITY и проверки HTTPS-сертификатов.

| Скрипт | Назначение | Результат |
| --- | --- | --- |
| [`reality_sni_finder.py`](reality_sni_finder.py) | Поиск доменов на HTTPS-серверах в соседних IPv4-подсетях `/24`, по умолчанию с проверкой TLS 1.3, HTTP/2 и сертификата | Текстовый список доменов, отсортированный по оценке задержки и близости IP |
| [`https_healthcheck.py`](https_healthcheck.py) | Проверка сертификата одного домена и, по запросу, HTTPS HEAD-запрос | JSON-отчёт и код завершения для автоматизации |

Скрипты запускаются отдельно. Они не создают конфигурацию Xray и не передают результаты друг другу автоматически.

## Требования и установка

Оба скрипта используют стандартную библиотеку Python: установка пакетов через `pip` не требуется.

| Компонент | SNI Finder | HTTPS Healthcheck |
| --- | --- | --- |
| Python | 3.9+ со сборкой SSL, поддерживающей TLS 1.3 | 3.11+ согласно требованиям скрипта |
| `masscan` в `PATH` | Обязателен | Не нужен |
| `openssl` в `PATH` | Обязателен для разбора сертификатов | Не нужен; используется модуль Python `ssl` |
| `curl` в `PATH` | Обязателен; для проверки по умолчанию нужна поддержка HTTP/2 и TLS 1.3 | Нужен только с `--http` |
| Права | Для `masscan` нужны права на отправку raw-пакетов, обычно через `sudo` | Повышенные права не требуются |

Для запуска обоих скриптов используйте Python 3.11+. Примеры Finder ниже рассчитаны на Linux. Healthcheck также можно запускать в Windows и macOS при наличии Python и, для `--http`, `curl`.

Пример установки системных пакетов в Debian/Ubuntu из каталога проекта:

```bash
sudo apt update
sudo apt install python3 masscan curl openssl ca-certificates

python3 --version
curl --version
python3 reality_sni_finder.py --help
python3 https_healthcheck.py --help
```

Проверьте версию Python; для Finder в выводе `curl --version` должна быть функция `HTTP2` и TLS-бэкенд с поддержкой TLS 1.3. Finder проверяет наличие всех трёх внешних утилит даже при `--no-verify-h2`.

## Загрузка на сервер и меню запуска

| Скрипт | Назначение |
| --- | --- |
| [`deploy.sh`](deploy.sh) | Загрузить текущие файлы проекта по SSH и запустить установщик на сервере |
| [`install.sh`](install.sh) | Установить системные зависимости Debian/Ubuntu и проверить окружение |
| [`run.sh`](run.sh) | Открыть меню проекта или запустить любой Python-скрипт напрямую |

Bash-оболочка требует Python 3.11+. В меню есть ASCII-логотип проекта, переключение русского/английского языка, поиск SNI, проверка HTTPS и проверка зависимостей. Перед запуском меню запрашивает цель и параметры. Для Finder в меню по умолчанию выбран `--blocks 0`; значение в Python CLI остаётся `6`. При запуске от обычного пользователя `sudo` запрашивает только команда Finder.

### Загрузка прямо с компьютера

Из каталога проекта на вашем компьютере, в Bash (в Windows — Git Bash):

```bash
bash deploy.sh user@server

# Свой путь на сервере; пропустить установку пакетов, если зависимости уже есть.
bash deploy.sh --dir /home/user/reality-tools --skip-deps user@server
```

Замените `user@server` на свой SSH-адрес. Используются ваши SSH-ключи, агент или обычная аутентификация по паролю. По умолчанию проект загружается в каталог `reality-tools` относительно домашнего каталога SSH-пользователя. Передаются текущие версии двух Python-скриптов, трёх Bash-скриптов, их тестов, README, лицензии и файлов `.gitignore`/`.gitattributes`, включая незакоммиченные изменения. Учётные данные, `.git` и результаты проверок не передаются. Повторная загрузка заменяет поставляемые файлы проекта и сохраняет результаты. Используйте отдельный каталог для проекта.

Установщик использует `apt-get` в Debian/Ubuntu и при необходимости запрашивает `sudo`. Он устанавливает Python, Git, `masscan`, `curl`, `openssl` и корневые сертификаты, затем проверяет Python 3.11+, поддержку TLS 1.3 в Python, наличие внешних утилит и HTTP/2 в `curl`. Если системный Python старее, установите подходящий интерпретатор и выберите его через `PYTHON_BIN`. В других дистрибутивах Linux установите зависимости самостоятельно и используйте `--skip-deps`.

После загрузки откройте меню:

```bash
ssh user@server
cd ~/reality-tools
bash run.sh

# Сразу выбрать русский или английский язык меню.
RSF_LANG=ru bash run.sh
RSF_LANG=en bash run.sh
```

### Запуск без меню

```bash
bash run.sh check
bash run.sh finder --ref-ip 192.0.2.10 --blocks 0 --top 10
bash run.sh healthcheck --authorized --http my-domain.example
mkdir -p results
bash run.sh healthcheck --authorized --output results/report.json my-domain.example

# Выбрать другой интерпретатор.
PYTHON_BIN=/usr/bin/python3.11 bash run.sh check
```

Флаги Python и коды завершения сохраняются. `bash run.sh finder --help` и `bash run.sh healthcheck --help` показывают справку соответствующего Python-скрипта. Относительные пути отсчитываются от каталога проекта. Finder по умолчанию пишет в `results/domains.txt`, а HTTPS-проверка из меню сохраняет JSON-отчёты с отметкой времени в `results/`. Прямая команда `healthcheck` выводит отчёт в stdout, если не указан `--output`; при необходимости заранее создайте родительский каталог файла. Переменная `RSF_RESULTS_DIR` меняет каталог результатов оболочки. Содержимое `results/` исключено из Git. Файл Finder, созданный через `sudo`, может принадлежать root.

Для проверки HTTPS по расписанию добавьте такую строку через `crontab -e`, подставив пользователя, пути и разрешённый вам домен:

```cron
0 */6 * * * /bin/bash /home/user/reality-tools/run.sh healthcheck --authorized --http my-domain.example >> /home/user/reality-healthcheck.log 2>&1
```

Проверка будет выполняться каждые шесть часов по часовому поясу сервера, а отчёты — добавляться в лог. При необходимости задайте в crontab абсолютный `PYTHON_BIN`. Для Finder без участия пользователя нужна задача от root или уже настроенные права на запуск `masscan` без запроса пароля. Загрузка и установка сами расписание не включают.

## Поиск SNI-кандидатов

### Быстрый запуск

Сканируйте только адреса и диапазоны, на проверку которых у вас есть разрешение. Автоматическое определение публичного IP не означает разрешения на сканирование соседних подсетей.

```bash
# Автоматически определить публичный IPv4 и проверить его /24 и по 6 соседних /24 с каждой стороны.
sudo python3 reality_sni_finder.py --verbose

# Явно задать опорный IPv4 и уменьшить охват до одной /24.
# Замените 192.0.2.10 на адрес из разрешённого вам диапазона.
sudo python3 reality_sni_finder.py --ref-ip 192.0.2.10 --blocks 0 --verbose

# Выбрать число результатов, файл и исключить известные общие CDN-домены.
sudo python3 reality_sni_finder.py --ref-ip 192.0.2.10 --blocks 0 --top 10 --no-include-generic --output candidates.txt
```

`192.0.2.10` — пример адреса для документации. Для реального запуска подставьте свой разрешённый IPv4. Без `--ref-ip` скрипт обращается к `api.ipify.org`, затем, при необходимости, к `ifconfig.me/ip` и `ipv4.icanhazip.com`.

### Как работает поиск

1. Строит диапазон из опорной `/24` и `N` подсетей с каждой стороны. По умолчанию это 13 подсетей, до 3328 IPv4-адресов; у границ IPv4 охват меньше.
2. Одним запуском `masscan` ищет открытый TCP-порт 443. Сам опорный IP исключается из дальнейших проверок.
3. Выполняет TLS-подключения без SNI и извлекает CN и DNS SAN из полученных сертификатов через локальный `openssl`. По умолчанию оставляет только соединения с TLS 1.3.
4. Превращает wildcard `*.example.com` в кандидатов `example.com` и `www.example.com`, фильтрует некорректные имена и ограничивает число доменов на IP.
5. По умолчанию проверяет каждую пару домен/IP через `curl --resolve`: запрос HEAD с SNI домена, TLS 1.3, доверенная цепочка сертификата, соответствие имени и фактически согласованный HTTP/2.
6. Ранжирует результаты и сохраняет уникальные домены, выбирая для каждого лучший результат.

Оценка равна времени `curl time_appconnect` в миллисекундах плюс штраф до 25 мс за числовое расстояние между IP-адресами. `time_appconnect` измеряет время от начала запроса до завершения TLS-подключения, включая установление TCP. При отсутствии этой метрики используется время начального подключения; если нет и его — 5000 мс. Числовая близость IP не измеряет географическую близость.

Серверы, которые не отвечают без SNI или возвращают без него сертификат другого виртуального хоста, могут не попасть в результаты. Полученный список — кандидаты; реальное подключение REALITY скрипт не проверяет.

### Параметры Finder

Аргументы командной строки имеют приоритет над переменными окружения. Значения ниже указаны для окружения без `RSF_*`.

| Параметр | Переменная окружения | По умолчанию | Описание |
| --- | --- | --- | --- |
| `--ref-ip` | `RSF_REF_IP` | Автоопределение | Опорный IPv4; IPv6 не поддерживается |
| `--blocks` | `RSF_BLOCKS` | `6` | Число соседних `/24` с каждой стороны; `0` — только опорная `/24` |
| `--rate` | `RSF_RATE` | `4000` | Скорость отправки пакетов `masscan`, пакетов/с |
| `--wait` | `RSF_WAIT` | `2` | Время ожидания ответов после отправки пакетов, с |
| `--timeout` | `RSF_TIMEOUT` | `8` | Тайм-аут `curl`, с; тайм-аут начальной TLS-пробы — `max(2.5, timeout - 2)` |
| `--threads` | `RSF_THREADS` | `64` | Число параллельных рабочих потоков |
| `--max-per-ip` | `RSF_MAX_PER_IP` | `8` | Максимум доменов из CN/SAN для одного IP |
| `--top` | `RSF_TOPN` | `30` | Максимум уникальных доменов в результате |
| `--output` | — | `domains.txt` | Путь к выходному файлу |
| `--include-generic` / `--no-include-generic` | `RSF_INCLUDE_GENERIC` | `1` — включено | Включать домены из встроенного списка общих CDN |
| `--verify-h2` / `--no-verify-h2` | `RSF_VERIFY_H2` | `1` — включено | Проверять через `curl` HTTP/2 и сертификат; TLS 1.3 зависит также от следующего флага |
| `--require-tls13` / `--no-require-tls13` | — | Включено | Требовать TLS 1.3 при начальной пробе и проверке через `curl` |
| `-v`, `--verbose` | — | Выключено | Печатать домены, выбранные IP и задержки |
| `-h`, `--help` | — | — | Показать справку |

Для логических переменных окружения используйте `1` или `0`. Например, `RSF_TOPN=10 python3 reality_sni_finder.py ...` задаёт число результатов, если `--top` не указан. При запуске через `sudo` передавайте параметры флагами: сохранение окружения зависит от настроек `sudo`.

`--no-include-generic` исключает только `cloudflaressl.com`, `cloudflare.com`, `akamai.net`, `akamaiedge.net`, `cloudfront.net`, `edgekey.net`, `edgesuite.net`, `fastly.net` и их поддомены. Это не универсальный фильтр всех CDN.

`--no-verify-h2` пропускает весь этап проверки через `curl`, включая проверку доверия и имени сертификата. Начальная TLS-проба сама сертификат не проверяет. `--no-require-tls13` разрешает TLS 1.2; требование HTTP/2 сохраняется, пока включён `--verify-h2`. Для поиска кандидатов REALITY оставьте обе проверки включёнными.

### Выходной файл

`domains.txt` или файл из `--output` содержит только домены, по одному на строку, в порядке оценки от лучшей к худшей:

```text
www.example.com
example.org
```

Файл записывается в UTF-8 и **перезаписывается** при успешном поиске. IP-адреса и задержки выводятся только с `--verbose` и в файл не попадают. Показанная задержка не включает штраф за расстояние IP. Если подходящие результаты не найдены, новый файл не создаётся, а прежний остаётся на месте.

## Проверка HTTPS-домена

### Быстрый запуск

Замените `my-domain.example` на домен, который вы вправе проверять. Флаг `--authorized` обязателен и подтверждает это право.

```bash
# Проверить доверие, имя и срок действия сертификата.
python3 https_healthcheck.py --authorized my-domain.example

# Дополнительно выполнить HTTPS HEAD и сохранить новый JSON-отчёт.
python3 https_healthcheck.py --authorized --http --timeout 10 --output report.json my-domain.example
```

В PowerShell можно использовать `python`:

```powershell
python https_healthcheck.py --authorized --http --output report.json my-domain.example
$LASTEXITCODE
```

### Поведение и параметры

Скрипт принимает одно DNS-имя в ASCII/Punycode без схемы, порта, пути или wildcard. IP-адреса, диапазоны и списки доменов не принимаются. Порт всегда 443.

Проверка использует обычное DNS-разрешение, SNI указанного домена и TLS 1.2 или новее. Проверяются системное доверие к цепочке сертификата и имя хоста по SAN; подстановка имени из CN отключена. При сроке до истечения **30 дней или меньше** возвращается предупреждение `warning`, которое само по себе не приводит к ошибке завершения.

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `domain` | Обязателен | Одно DNS-имя для проверки |
| `--authorized` | Обязателен | Подтверждение права на проверку домена |
| `--http` | Выключено | После успешной проверки сертификата выполнить один HTTPS HEAD-запрос через `curl` |
| `--timeout` | `8` | Целое число от 2 до 30 с для каждого этапа отдельно; не общий лимит всего запуска |
| `--output` | Не задан | Сохранить отчёт в новый JSON-файл; родительский каталог должен существовать |
| `-h`, `--help` | — | Показать справку |

С `--http` запрос отправляется напрямую, без прокси и пользовательского файла конфигурации `curl`. Перенаправления не отслеживаются. HTTP/2 не обязателен: отчёт содержит фактически использованную версию HTTP. Ответы 4xx/5xx записываются в отчёт и сами по себе не считаются ошибкой диагностики. Если проверка сертификата не удалась, HTTP-этап получает статус `skipped`.

### JSON-отчёт

Отчёт всегда выводится в stdout после выполнения диагностики и, с `--output`, дополнительно сохраняется в файл. Время указано в UTC. Ниже условный успешный результат с `--http`:

```json
{
  "schema_version": 1,
  "checked_at_utc": "2026-11-24T09:00:00Z",
  "domain": "my-domain.example",
  "port": 443,
  "ok": true,
  "certificate": {
    "status": "ok",
    "certificate_verified": true,
    "expires_at_utc": "2027-02-22T09:00:00Z",
    "days_remaining": 90.0,
    "expiry_warning": false
  },
  "http": {
    "status": "ok",
    "method": "HEAD",
    "http_version": "2",
    "http_status": 200
  }
}
```

Без `--http` объект `http` содержит `{"status": "not_requested"}`. При ошибке соответствующий этап содержит `status: "error"`, `error_type` и `error`; поля успешного результата могут отсутствовать. Поле `ok` отражает успешность запрошенных этапов, включая допустимое предупреждение о сроке сертификата.

Существующие файлы и символьные ссылки **не перезаписываются**. Если путь уже занят до запуска проверки, скрипт завершится с кодом `2`; ошибка записи после диагностики даёт код `3`.

### Коды завершения

| Код | Finder | Healthcheck |
| --- | --- | --- |
| `0` | Список доменов записан | Диагностика успешна; предупреждение о скором истечении допустимо |
| `1` | Ошибка поиска, зависимости или отсутствие подходящих результатов | Ошибка проверки сертификата или запрошенного HTTP-этапа |
| `2` | Ошибка разбора аргументов | Неверные аргументы, нет `--authorized` или выходной путь уже занят |
| `3` | Не используется явно | Не удалось сохранить отчёт после диагностики |
| `130` | Не задаётся явно | Проверка отменена через Ctrl+C |

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| `Required tool not found in PATH` | Установлены ли `masscan`, `curl`, `openssl` и доступны ли они в окружении запуска Finder, в том числе под `sudo` |
| `masscan failed` | Права на raw-пакеты, доступность сетевого интерфейса и подробности ошибки; при потерях ответов уменьшите `--rate` |
| Нет результатов после строгой проверки | Поддержку HTTP/2/TLS 1.3 в `curl`, доступность серверов и системные корневые сертификаты; при необходимости увеличьте `--timeout` |
| Healthcheck сообщает ошибку сертификата | Соответствие SAN домену, срок сертификата, полноту цепочки сервера, системное время и корневые сертификаты |
| JSON-отчёт не сохраняется | Существует ли каталог, есть ли права записи и свободно ли выбранное имя файла |
